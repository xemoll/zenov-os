ZenovOS 0.1.1 - installation and virtual-machine boot guide
=============================================================

ZenovOS provides three system images:

- ZenovOS-0.1.1-x86.iso   bootable BIOS/El Torito virtual CD
- ZenovOS-0.1.1-x86.img   bootable 1.44 MiB FAT12 fallback image
- ZenovOS-0.1.1-data.img  writable 16 MiB ATA/ZenovFS data volume

The ISO and FAT12 IMG contain the same verified ZenovOS boot filesystem. The ISO
uses El Torito floppy emulation so existing BIOS boot code remains unchanged.
User files, configuration, native applications, package state and security audit
records are stored on the separate writable data image and survive a reboot.

The ISO is a live boot medium, not a hard-disk installer. Legacy BIOS is required;
UEFI and installation to physical hardware are not supported in this build.

QUICK START WITHOUT ZIP
-----------------------
1. Download ZenovOS-0.1.1-x86.iso and ZenovOS-0.1.1-data.img.
2. Create a 32-bit x86 virtual machine using legacy BIOS.
3. Attach the ISO as a virtual CD/DVD.
4. Attach the data image as the first IDE hard disk.
5. Put the optical drive first in the boot order and start the VM.

QEMU - MANUAL COMMAND
---------------------
qemu-system-i386 \
  -m 64M \
  -drive file=ZenovOS-0.1.1-data.img,format=raw,if=ide,index=0,media=disk \
  -drive file=ZenovOS-0.1.1-x86.iso,format=raw,if=ide,index=2,media=cdrom,readonly=on \
  -boot order=d,strict=on

The packaged run-qemu.sh and run-qemu.cmd launch the ISO automatically when it
is present and fall back to the raw FAT12 image otherwise.

VIRTUALBOX
----------
1. Create a new 32-bit "Other/Unknown" virtual machine.
2. Disable EFI. Use one CPU and at least 64 MiB RAM.
3. Attach ZenovOS-0.1.1-x86.iso to the IDE optical drive.
4. Attach ZenovOS-0.1.1-data.img as an IDE hard disk.
5. Put Optical before Hard Disk in the boot order and start the VM.

VMWARE
------
1. Create an "Other 32-bit" virtual machine using BIOS firmware.
2. Attach ZenovOS-0.1.1-x86.iso to the virtual CD/DVD drive.
3. Attach ZenovOS-0.1.1-data.img as an existing IDE disk. Some VMware products
   require converting the raw data image to VMDK before attachment.
4. Boot from CD/DVD.

Automated acceptance is performed under QEMU. VirtualBox and VMware launch paths
are documented compatibility targets but are not currently exercised in CI.

RAW FLOPPY FALLBACK
-------------------
qemu-system-i386 \
  -m 64M \
  -drive file=ZenovOS-0.1.1-x86.img,format=raw,if=floppy \
  -drive file=ZenovOS-0.1.1-data.img,format=raw,if=ide,index=0,media=disk \
  -boot a

MEMORY AND SYSTEM DIAGNOSTICS
-----------------------------
ZenovOS 0.1.1 enables 4 KiB paging, an E820 physical frame allocator and a reusable
split/coalesce kernel heap. Boot self-tests allocate and release multiple physical
frames and fragmented heap blocks before storage and userspace are initialized.

pmm      physical frame counts and managed memory
vm       CR0, CR3 and active kernel/user mappings
mem      E820, heap and free-frame summary
memmap   BIOS E820 regions

PERSISTENT STORAGE
------------------
ZenovFS1 is mounted at /data. File replacement uses a copy-on-write data slot followed
by a sector-atomic metadata commit. Mount recovery discards an uncommitted staging
entry or completes a committed replacement, preserving old-or-new file contents.
Useful commands:

pwd
ls
mkdir PROJECTS
write NOTES.TXT hello
append NOTES.TXT world
cat NOTES.TXT
cp NOTES.TXT COPY.TXT
mv COPY.TXT ARCHIVE.TXT
stat ARCHIVE.TXT
fsck
sync
rm ARCHIVE.TXT
df
mount

NATIVE APPLICATIONS
-------------------
ZenovOS 0.1.1 supports two validated native formats:

- ZEX1, the compact deterministic ZenovOS executable container
- static 32-bit little-endian i386 ELF executables within the user window

Included applications:

run HELLO
run FILEIO.ELF
run ARGS.ELF alpha beta
run CONSOLE.ELF
run PROTECT.ELF
run KACCESS.ELF
run ZENOVAPP.ZEX

FILEIO.ELF validates the file syscall ABI and persistent data. ARGS.ELF validates
argc/argv, stable error codes and guarded userspace pointers. CONSOLE.ELF validates
bounded console input. PROTECT.ELF and KACCESS.ELF deliberately fault to prove that
RX code pages and supervisor state remain protected and that control returns to the
shell. ZENOVAPP.ZEX is compiled from the documented Zenov freestanding subset.

ZEX/ELF support does not provide Windows PE or DOS MZ compatibility. Arbitrary
Windows or DOS .exe files are not supported. Dynamic ELF linking is not supported.

VERIFY THE DOWNLOAD AND PROVENANCE
----------------------------------
SHA256SUMS.txt verifies the ISO, raw boot image, writable data image, ZIP, build
manifest, source revision and installation guide:

sha256sum -c SHA256SUMS.txt

Inside the optional ZIP:

- IMAGE-SHA256SUMS.txt verifies the ISO, both IMG files, BUILD-MANIFEST.json and
  SOURCE-REVISION.txt.
- BUILD-MANIFEST.json records image hashes, the Zenov app ABI, canonical app hash,
  the merged Zenov compiler repository revision and the OS-side compiler source hash.
- SOURCE-REVISION.txt records the exact ZenovOS commit used to create the package.

Run this after extraction:

sha256sum -c IMAGE-SHA256SUMS.txt
