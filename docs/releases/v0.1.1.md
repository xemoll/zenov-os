# ZenovOS 0.1.1

**Published:** 16 July 2026  
**Tag:** `v0.1.1`  
**Source commit:** [`22a3eec9b97b0ef0fac35be641c2526c577b1964`](https://github.com/xemoll/zenov-os/commit/22a3eec9b97b0ef0fac35be641c2526c577b1964)  
**Target:** 32-bit x86 / `i686-zenov-none`

ZenovOS 0.1.1 is an architectural release focused on virtual memory, isolated native applications and more reliable persistent storage. It is a bootable standalone operating-system image, not a Linux distribution and not a Windows or macOS compatibility layer.

> [!IMPORTANT]
> These notes document the immutable files attached to the `v0.1.1` tag. The repository's `main` branch contains substantial later work that still carries the internal `0.1.1` version number. Those later desktop, security, package and storage changes are not automatically present in the original release download.

## Highlights

- E820-based physical-memory discovery and frame allocation;
- 4 KiB paging with supervisor-only kernel mappings;
- isolated ring-3 execution for ZEX1 and validated static ELF32/i386 applications;
- expanded file syscalls and a persistent ELF32 file-I/O demonstration;
- stronger ZenovFS image and checksum verification;
- two-boot persistence validation;
- deterministic installation packaging and checksum output.

## Changes since 0.1.0

The `v0.1.1` tag is two commits ahead of `v0.1.0`.

### Memory management

- Added E820 memory-map parsing.
- Added a physical frame allocator.
- Added 4 KiB paging.
- Kept kernel mappings supervisor-only.
- Added explicit runtime evidence for physical-memory and paging initialization.

### Native application support

- Retained the native ZEX1 loader.
- Added a bounded static ELF32/i386 loader.
- Validated ELF headers and loadable segments before execution.
- Added a dedicated ring-3 process ABI contract for version 0.1.1.
- Added `FILEIO.ELF` as a persistent file-I/O application test.

### System-call ABI

The release exposes the following `INT 0x80` calls:

```text
0  exit
1  write_console
2  get_ticks
3  file_read
4  file_write
5  file_stat
6  get_version
7  sync
```

File operations use bounded userspace buffers and the release verifies that data written by a ring-3 application remains available after reboot.

### Persistent storage

- Continued to use ATA PIO with a separate writable ZenovFS data image.
- Added kernel-side and host-side ZenovFS integrity checks.
- Added `fsck` verification to the QEMU release path.
- Added a second boot phase to verify persisted shell and application data.
- Preserved the boot image separately from writable system data.

### Build and release engineering

- Updated the build target and package names from 0.1.0 to 0.1.1.
- Added deterministic system and installation-package rebuild checks.
- Added release checks for the exact boot, paging, application and persistence markers.
- Added a public installation archive, raw boot image, installation guide and SHA-256 verification file.

## Downloads

### Recommended

`ZenovOS-0.1.1-x86.zip`

The archive contains the boot image, writable ZenovFS data image, installation instructions and QEMU launchers for Unix-like hosts and Windows.

### Raw image

`ZenovOS-0.1.1-x86.img`

This is the raw FAT12 boot image. Persistent operation also requires the writable data image included in the ZIP archive.

### Verify the download

Use the supplied checksum file from the release:

```bash
sha256sum -c SHA256SUMS.txt
```

## Run in QEMU

Extract the ZIP and use the included launcher. The packaged configuration keeps the boot image and writable ZenovFS data image separate so changes persist between boots.

For a source build:

```bash
sudo apt-get update
sudo apt-get install -y build-essential binutils qemu-system-x86 openssl zip unzip

git clone https://github.com/xemoll/zenov-os.git
cd zenov-os
git checkout v0.1.1

make
make qemu
```

## Known limitations

- BIOS and 32-bit x86 only;
- QEMU is the verified runtime target for this release;
- one foreground userspace application;
- static ZEX1 and ELF32/i386 applications only;
- no dynamic linker or POSIX compatibility layer;
- no networking or audio stack;
- Windows PE, DOS MZ, macOS and console executables are not supported;
- the original release predates later `main` work on the graphical desktop, ZenovGuard policy domains, ZenPkg Runtime Provider ABI, advanced ATA recovery and TPM 2.0.

## Release integrity

The tag and downloadable assets should be treated as one immutable unit. When reporting a problem, include:

- the source revision or tag;
- the SHA-256 of the downloaded archive or image;
- the QEMU version and launch command;
- the serial log;
- whether the writable data image was new or reused.
