# ZenovOS 0.1.1 VM Image 4

VM Image 4 repairs the Linux/macOS VirtualBox launch path when the host cannot expose AMD-V/VT-x to VirtualBox.

## User-visible fix

The release still contains the same boot model: a read-only BIOS El Torito ISO and a separate writable ZenovFS disk. The updated `prepare-vm.sh` now:

- reuses and repairs an existing powered-off VirtualBox VM instead of refusing it;
- applies one CPU, 64 MiB RAM, legacy BIOS, optical-first boot and disabled networking;
- recognizes `VERR_SVM_DISABLED`, `VERR_SVM_IN_USE`, `VERR_VMX_NO_VMX`, `VERR_VMX_IN_VMX_ROOT_MODE`, `VERR_NEM_NOT_AVAILABLE` and the Hyper-V raw-mode error;
- falls back to QEMU TCG with the same ISO and VDI when VirtualBox cannot access hardware virtualization;
- allows the fallback to be disabled explicitly;
- refuses to modify a running VM.

For an existing VM named `gergre`:

```bash
ZENOV_VM_NAME=gergre ./prepare-vm.sh virtualbox
```

Force software emulation:

```bash
ZENOV_VM_NAME=gergre ZENOV_QEMU_ACCEL=tcg ./prepare-vm.sh virtualbox
```

QEMU TCG does not require AMD-V/VT-x, but is slower than hardware virtualization. On Arch or CachyOS install the host tools with:

```bash
sudo pacman -S --needed qemu-system-x86 qemu-img
```

## Verification

`tests/vm_launcher_test.sh` provides a deterministic fail-closed matrix for:

- repair of the existing `gergre` VM;
- successful VirtualBox start;
- `VERR_SVM_DISABLED` fallback to QEMU TCG;
- fallback disablement;
- refusal to modify a running VM;
- direct QEMU TCG launch.

The test is part of `make vm-check`, the BIOS/VM workflow and the VM Image 4 publication gate. The release pipeline also repeats optical boot, two-boot persistence, ZenovFS fsck, disk-container round trips, lifecycle-manager acceptance and complete release checksum verification.

## Boundary

No guest ISO, VDI or kernel can enable AMD-V/VT-x in the host firmware or take it away from another host hypervisor. VM Image 4 fixes the distributed launcher by using a software-emulation path when VirtualBox cannot start. Native VirtualBox acceleration still requires AMD-V/VT-x to be available to VirtualBox.
