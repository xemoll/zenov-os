# ZenovOS 0.1.1 VM Image 2

**Status:** staged; publish only after the exact source commit passes all required workflows.  
**Target:** legacy BIOS, 32-bit x86 virtual machines.

VM Image 2 extends the verified optical-boot distribution with direct multi-hypervisor writable disks, cross-platform preparation helpers and a real two-boot persistence acceptance test.

## Planned direct downloads

- `ZenovOS-0.1.1-x86.iso` — read-only BIOS El Torito boot medium;
- `ZenovOS-0.1.1-data.img` — canonical raw ZenovFS image;
- `ZenovOS-0.1.1-data.qcow2` — QEMU/KVM writable disk;
- `ZenovOS-0.1.1-data.vdi` — VirtualBox writable disk;
- `ZenovOS-0.1.1-data.vmdk` — VMware writable disk;
- `ZenovOS-0.1.1.vmx` — VMware Workstation/Fusion configuration;
- `prepare-vm.sh` and `prepare-vm.ps1` — cross-platform preparation helpers;
- `VM-QUICKSTART.txt` — concise hypervisor setup and backup instructions;
- `VM-APPLIANCE-MANIFEST.json`, `BUILD-MANIFEST.json`, `SOURCE-REVISION.txt` and `SHA256SUMS.txt` — provenance and verification metadata.

No ZIP extraction is required for the direct VM distribution.

## Verification required before publication

The publication source must pass:

- BIOS El Torito metadata and embedded FAT12 image comparison;
- normal optical boot to the graphical desktop;
- two optical boots using the same writable QCOW2 disk;
- a write plus `sync` during the first boot;
- payload replay and `fsck` during the second boot;
- QCOW2, VDI and VMDK consistency checks;
- conversion of every convenience disk back to raw;
- byte-for-byte comparison with the canonical ZenovFS image before guest mutation;
- direct no-ZIP asset checksum validation;
- the repository's ordinary exact-head regression workflows.

## Reproducibility boundary

The ISO, canonical raw images, scripts, documentation and manifests are deterministic. QCOW2, VDI and VMDK container metadata may include format-specific identifiers generated by `qemu-img`; the proven reproducibility boundary is the guest-visible disk content, which must round-trip to the canonical raw image byte-for-byte.

## Current limitations

- live BIOS boot rather than a hard-disk bootloader installation;
- no UEFI boot;
- no physical-hardware installer;
- no networking, audio, guest additions/tools or accelerated 3D;
- QEMU is the automated runtime acceptance target;
- VirtualBox and VMware assets are structurally and semantically verified, but those proprietary hypervisors are not executed in GitHub-hosted CI.
