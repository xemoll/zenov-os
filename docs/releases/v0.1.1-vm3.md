# ZenovOS 0.1.1 VM Image 3

**Release:** [`v0.1.1-vm3`](https://github.com/xemoll/zenov-os/releases/tag/v0.1.1-vm3)  
**Target:** legacy BIOS, 32-bit x86 virtual machines  
**Distribution:** 15 directly downloadable assets

VM Image 3 is the current integrated ZenovOS virtual-machine distribution. It replaces the older VM Image 2 recommendation and contains the bootable ISO, writable hypervisor disks and the transactional lifecycle manager produced from one exact source revision.

The release workflow records the exact source commit in the release body, `SOURCE-REVISION.txt` and `BUILD-MANIFEST.json`. Exact SHA-256 values are published in `SHA256SUMS.txt` rather than duplicated as mutable placeholders in this document.

No ZIP extraction is required. The ISO is a read-only ISO 9660 / El Torito boot medium. Persistent files, settings, packages, security state and audit records live on the separate writable ZenovFS disk.

## Publication guarantees

The release transaction is fail-closed:

1. the workflow checks out one exact `main` commit;
2. `make all vm-check` rebuilds and verifies the ISO and all writable formats;
3. El Torito metadata, QEMU optical boot, graphical desktop readiness and two-boot ZenovFS persistence are required;
4. RAW, QCOW2, VDI and VMDK lifecycle operations, tamper rejection, locking, backup, reset and restore are exercised;
5. exactly 15 assets and their SHA-256 entries are verified;
6. a draft GitHub Release is created and every uploaded asset is downloaded again and compared byte-for-byte;
7. the draft is made public only after the complete asset-name set and release body match;
8. the ISO is finally downloaded through its public `browser_download_url` with `GH_TOKEN` removed and compared byte-for-byte with the verified local ISO.

A failed draft transaction is removed only when both the draft target and tag match the exact source being published. Existing public or mismatched releases are never overwritten.

## VM settings

| Setting | Value |
| --- | --- |
| Architecture | 32-bit x86 / i686 |
| Firmware | Legacy BIOS; disable EFI/UEFI |
| RAM | 64 MiB |
| CPU | One virtual CPU |
| CD/DVD | `ZenovOS-0.1.1-x86.iso` |
| Primary IDE disk | Exactly one matching writable data image |
| Boot order | CD/DVD first |
| Network | Disabled |

QEMU example:

```bash
qemu-system-i386 \
  -machine pc,vmport=off \
  -m 64M \
  -vga std \
  -drive file=ZenovOS-0.1.1-data.qcow2,format=qcow2,if=ide,index=0,media=disk \
  -drive file=ZenovOS-0.1.1-x86.iso,format=raw,if=ide,index=2,media=cdrom,readonly=on \
  -boot order=d,strict=on
```

## Lifecycle manager

`manage-vm.sh` supports:

```text
status
create
verify
backup
restore
reset
remove
```

Runtime formats are selected through `ZENOV_VM_FORMAT=raw|qcow2|vdi|vmdk`. The manager validates the canonical seed and image structure, uses temporary verified replacements, creates checksum sidecars for backups and rejects unsafe paths, symlinks, corrupted backups and concurrent mutations.

## Boundary

VM Image 3 remains a live BIOS boot distribution with a separate writable data disk. It does not implement UEFI boot, hard-disk bootloader installation, partitioning or installation on physical hardware. QEMU is the automated runtime acceptance target. VirtualBox and VMware containers are structurally and semantically verified, but those proprietary hypervisors are not executed in GitHub-hosted CI.
